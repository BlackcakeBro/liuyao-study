# 装卦六亲与古籍参考重组设计

**日期：** 2026-07-28  
**状态：** 用户已选定方案 A，待审阅本设计后进入实施计划。  
**范围：** 新版（extended）课程页 `lecture0725` 与 `casting`；默认经典版的既有路径和内容不改变。

## 目标

将已经进入课程主线的纳甲装支、世应和六亲内容完整归入“装卦六亲”课程页；将原“古籍预习”改为“古籍参考”，只承担模拟起卦、可追溯的原著参考和与课程对应的古籍案例分析。同步修正课程页“判断边界”底部文字紧贴左外边框的问题。

## 信息架构

### 1. 装卦六亲（`#lecture0725`）

课程按学习依赖顺序组织：

1. **装卦三步**：保留现有总览，明确“装支 → 定世应 → 安六亲”的骨架。
2. **纳甲装支**：迁入现有三画卦选择与内外卦装支互动实验室；说明只讲已学的装支原理，不把古籍表格冒充课堂新增结论。
3. **世应定位**：将现有世应角色说明与宫内世应序位实验室放在同一课程段，先解释“我／所测”，再查看序位规则。
4. **六亲生克**：保留双环五行关系图，并迁入六亲总览卡；卡片仅作关系和取象入口。
5. **父母爻与官鬼爻**：保留本课已讲的三层取象重点；子孙、妻财、兄弟仍标示为后续课堂，不补写未讲内容。
6. **判断边界**：保留“没有脱离占问的固定吉凶”与后续课堂提示。

所有迁入模块保留原有 DOM id 和渲染数据接口，避免改变 `app.js` 的既有交互初始化路径；只调整它们在新版 DOM 中的归属、标题、序号和课程语境。

### 2. 古籍参考（`#casting`，仅新版）

新版页面标题改为“古籍参考”。内容顺序为：

1. **模拟起卦**：完整保留，仍只用于巩固爻序与动变，不代替正式占问。
2. **原著参考**：用来源卡或索引列出与当前课程对应的原著章节，例如纳甲、世应、六亲、动变／取用；每项显示书名、章节（或卷次）及使用目的。它是索引而不是第二套课堂。
3. **案例分析**：选择本地已收录古籍中的原例，围绕当前已学的装支、世应、六亲、父母爻或官鬼爻呈现“原例出处 → 卦中结构 → 可观察点 → 课程边界”。不改写或虚构原例；无法可靠定位卷次、篇名或原文的材料不展示。
4. **后续参考**：保留取用神等尚待课堂推进的古籍参考入口，并明确其为参考，不作为已完成课程。

“当前学习界线”路线图、纳甲实验室、世应实验室、六亲卡片不再位于古籍页。古籍页可提及这些知识的原著出处，但不得再以“预习模块”呈现。

### 3. 判断边界视觉

`.judgment-boundary` 作为深色内嵌面板增加与标题、规则一致的响应式左右内边距。底部“后续课堂”保留跨列结构，但与面板内容线对齐；桌面、平板和手机均不出现文字贴边、越界或与边框重合。分隔线保持在内边距范围内。

## 数据与内容边界

- 课程内容仍以陈师实际课程为主；古籍卡片与案例必须标注来源。
- 原著与案例的可选来源不限于《增删卜易》；可以使用本地古籍合集内的其他原著，例如《卜筮正宗》《火珠林》等，但每个展示条目必须可回溯。
- 不将古籍推论表述为教师已讲内容；不补造子孙、妻财、兄弟的课程讲解。
- 训练导航、模块名称和说明统一使用“古籍参考”，不再使用“古籍预习”或“古籍装卦校注”。

## 实现边界

- 修改范围预计为 `liuyao-study-github/index.html`、`styles.css`、`app.js` 和 `training-bank.js`；如需新增可维护的来源／案例数据，优先放在现有数据文件而非散落在模板中。
- 经典版路径以 `data-edition-only="classic"` 隔离；不得移动或改写其既有内容与交互。
- 不改变模拟起卦的算法、题目答案或既有课程数据的知识断言，除非命名或页面归属需要同步引用。

## 验证

1. 更新或新增针对页面结构、模块归属、命名和来源字段的静态／单元测试。
2. 运行既有测试套件与语法检查。
3. 在新版桌面、平板、移动视口核验：课程顺序、六亲互动模块、判断边界内边距、古籍参考的来源与案例布局。
4. 切换默认经典版，确认其 `casting` 内容和流程未受影响。
5. 对受保护旧版文件执行哈希或差异核验；只发布新版允许修改的文件。

## 异常处理

- 若某古籍案例无法从本地原文可靠定位，则不进入页面，宁缺毋滥。
- 若某版式在窄屏中无法保持双列阅读，则切换为单列，来源标注不截断。
- 若课堂与古籍存在表述差异，页面显示“古籍参考”边界并以课程口径为主，不自行裁决版本差异。
